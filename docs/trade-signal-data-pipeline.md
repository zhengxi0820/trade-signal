# trade-signal 数据管线（数据源与复权体系）

> `scripts/`（python）数据灌入管线的设计口径权威文档。命令用法见 [../scripts/README.md](../scripts/README.md)，本文档负责"为什么这么设计、口径是什么、有哪些坑"。表结构以 [trade-signal-schema.sql](trade-signal-schema.sql) 为准。

## 1. 定位与架构

薄脚本层，与 Java 主体**通过数据库解耦**：python 只写库，Java 只读库（Java 侧不落任何计算结果）。

```
akshare（三源）──► scripts/fetch（取数）──► scripts/adjust（因子反推复权）──► trade_signal 库 ──► Java 只读
```

写入的四张表：

| 表 | 内容 | 写入方式 |
|---|---|---|
| `stock_info` | 股票基础信息（name/market 唯一来源、board_type 板块枚举） | 全量灌入，akshare 名单接口 |
| `stock_quote` | 日线 OHLCV：`ADJUST='0'` 原始行 + `ADJUST='1'` 自算前复权行 | 原始行只追加；qfq 行可重算覆盖 |
| `stock_dividend` | 除权除息事件（EX_DATE + 综合因子 k，SOURCE='derive'） | 因子反推生成，只追加 |
| `work_day` | 交易日历（`/kdj/periods` 来源） | 从 stock_quote distinct TRADE_DATE 生成 |

ID 规则：`stock_quote`=MD5(code:yyyymmdd:adjust)、`stock_dividend`=MD5(code:ex_date)、`work_day`=MD5(market:trade_date)；时间戳一律 UNIX 秒（DECIMAL(15,0)）。

## 2. 数据源实测口径（2026-08，本机实测）

| 源 | 状态 | 说明 |
|---|---|---|
| **新浪 `stock_zh_a_daily`（主源）** | 可用 | **等比前复权**，factor 阶梯干净（平台波动 ~1e-5）；沪深北通吃；成交量单位为股；**数据滞后一个交易日**（daily 回看 10 天覆盖） |
| 东财 `stock_zh_a_hist` | 不可用（留兜底） | 本机 push2his 直连被重置、代理 502；网络恢复后自动启用 |
| 腾讯 `stock_zh_a_hist_tx` | **弃用** | 其 qfq 是**等差（减法）复权**：段内 qfq=raw−C，factor 随价格漂移，不是阶梯，会产生大量伪事件（实测踩过并清理） |

其他口径：

- 每股必须爬**两口径**（`adjust=""` 与 `adjust="qfq"`）且**必须同源**（复权基期才一致）
- 北交所代码 2024 年起已整体迁移 920 段（如 贝特瑞 835185→920185），板块前缀规则 `92x→'3'` 已覆盖
- 取数纪律：`NO_PROXY=*` 强制直连（本机系统代理会致抓取失败）、串行真限流、指数退避重试 3 次、东财失败切新浪

## 3. 复权：因子反推法

**不爬除权明细、不依赖涨跌停阈值**。每股爬两口径价格，`factor(t) = qfq(t) ÷ raw(t)` 是**阶梯函数，只在除权日跳变**，跳变倍数即综合因子（红利/送转/配股合并效果，无需明细字段）。

- **事件判定五道闸（全 AND）**：
  ① factor 日际相对变化 >0.1%；② 隐含金额变化（×当日股价）>0.005 元（原始双阈值，静默过滤）；
  ③ **噪声自适应幅度下限**：|相对变化| > 1.5 × 0.01 元 ÷ 股价——factor 由两个各自 0.01 元舍入的价格相除得到，常数平台上逐日 factor 的舍入状态游走最大可达 ~1 个最小价位/股价（相对值），跳变幅度必须明显超出该噪声带才可能是真事件；对高价股此项趋近于零（茅台仅 0.0009%），无副作用；
  ④ **方向过滤**：等比前复权下除权日 factor 只会向 1 跳升（k = 前÷后 < 1），降向候选（k ≥ 1）物理上不可能是除权，直接丢弃；
  ⑤ **跳变持续性后验**：候选跳变点之后 5 个交易日的 factor 中位数须 ≥ 旧平台 + 0.5 ×（新平台 − 旧平台）——真除权后 factor 永久稳定在新平台，伪跳变（舍入振荡）数日内振荡回原平台
- **被弃候选留痕**：③④⑤ 丢弃的候选连同原因（amplitude / direction / persistence）保留在 FactorSeries.rejected，`scripts/verify_fix.py` 只读复跑可审计
- **事件因子 k**：跳变点前后各约 10 个交易日 factor 中位数相除。等比前复权下除权日 factor 向 1 跳**升**，故 k = 前 ÷ 后 < 1（每日增量"历史 qfq 行 ×= k"依赖此方向约定）
- **落库原则**：爬的 qfq 只作反推原料与对拍基准，**落库一律自算** `qfq = raw × factor`（平台段中位数）——任何时刻库里 qfq 可由 raw + factor 表重算，可审计
- 对拍校验：自算 qfq vs 爬取 qfq 全序列，相对偏差 >0.1% 报警

### 3.1 历史回填流程（每股 2 次调用）

爬 none 全历史落库 → 爬 qfq 全历史（原料）→ 逐日 factor → 阶梯识别事件写 stock_dividend → 自算 qfq 落库 → 全序列对拍。

### 3.2 每日增量流程（每股 2 次调用）

爬当日两口径 → factor_当日 vs 库存最新 factor → 过与历史回填同款的闸①~④（相对/金额/幅度下限/方向）→ 无变化直接落库；候选事件再过闸⑤持续性后验（用 daily 10 天回看窗口内该日之后的逐日 factor；后续不足 5 日则**延期判定**，当日行不落库、下次窗口前移后重评）→ 确认事件则 k=旧÷新 → stock_dividend 追加 → 该股历史 qfq 行 ×= k → 当日行落库。

### 3.3 调度

脚本是一次性 CLI（跑完即退），由 **OS 级调度**触发：本机 Windows 任务计划、服务器 crontab（盘后，如交易日 17:30）。不用 python 常驻进程定时（APScheduler 等）——无常驻看护、无内存泄漏累积、退出码可接告警。
