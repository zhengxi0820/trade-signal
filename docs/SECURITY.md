# 服务器与服务安全基线规范

> 适用对象：公网部署的 Web 服务 + 云服务器。
> 核心假设：**公网环境默认敌意**。服务上线第一天就会被全网扫描器反复试探——本规范所有条目都是"被真实攻击验证过"或"标准行业基线"。
> 使用方式：上线前逐项打勾；任何一项做不到，记录理由和补偿措施。

## 〇、四条总原则

1. **纵深防御**：任何单层被击穿都不应导致全局失守（例：安全组拦一层 + 应用绑 127.0.0.1 再拦一层）。
2. **最小权限**：账号、端口、文件、API 密钥，只给完成工作所必需的最小权限。
3. **密码登录不存在才是防线**：暴力破解只能打"存在的锁孔"。靠强密码防爆破是侥幸心理（真实案例：root 弱密码 1630 次尝试被打穿）。
4. **密钥即命门**：凭据只存环境变量/密钥管理服务，严禁入仓；泄露不追查"有没有被用"，直接轮换。

## 一、服务器层（OS / 网络 / SSH）

### 1.1 装机顺序（顺序不可逆）

**先焊门，再装任何服务。** 新机/重装后第一小时是暴露窗口期，扫描器几分钟内就会找到你。

1. 绑定运维公钥（控制台或手动写入 `~/.ssh/authorized_keys`）
2. 验证密钥能登录（**先确认能进，再关门**，顺序反了会把自己锁外面）
3. 关闭密码认证：
   ```bash
   echo "PasswordAuthentication no
   KbdInteractiveAuthentication no" | sudo tee /etc/ssh/sshd_config.d/99-key-only.conf
   sudo sshd -t && sudo systemctl reload ssh
   ```
4. 双向验证：`sudo sshd -T | grep passwordauthentication` 必须输出 `no`；另一终端密码试登应返回 `Permission denied (publickey)`
5. fail2ban 兜底（失败 5 次封 24h）——即便密钥时代也该装，它能压掉扫描噪音并在配置被误改时兜底

### 1.2 SSH 加固

- 禁止 root 直登：`PermitRootLogin no`（用普通用户 + sudo）
- 密钥类型 ed25519；私钥永不出本机、不发 IM/邮件；换电脑 = 新机器生成新密钥对、追加公钥，**不拷贝私钥**
- 改默认 22 端口：可选。只能减少扫描噪音，不是防线，别用它替代关密码认证

### 1.3 网络边界

- 云安全组 + 主机防火墙（ufw）双层：默认全拒，只放行必需端口（通常 22/80/443）
- **数据库、缓存、消息队列、管理端口（3306/6379/8080/9000…）永不对公网开放**，且应用侧同时绑 `127.0.0.1`（双层）
- 服务间调用走内网/回环，不走公网

### 1.4 系统卫生

- 自动安全更新：`unattended-upgrades`（Ubuntu）或等效机制
- 服务以专用非 root 用户运行；sudo 权限最小化
- 敏感文件权限：凭据文件 `chmod 600`，属主为专用用户
- 云控制台：开启 MFA；API 密钥用子账号 + 最小权限；开启登录/爆破告警通知

### 1.5 可观测与兜底

- 认证日志（`/var/log/auth.log`）有人看或有告警；fail2ban 状态定期巡检
- 部署验证完毕后**打一个干净基线快照**；严禁恢复到"入侵前旧快照"（会把已泄露凭据带回来）
- 数据每日备份 + **恢复演练**（备份没演练过等于没有）

## 二、服务/应用层

### 2.1 认证与会话

- **任何公网可达的服务必须有认证**，没有"临时先裸奔"这个状态
- 口令/密钥走环境变量，登录换 HttpOnly Cookie（不存明文口令）
- Cookie 三件套：`HttpOnly` + `Secure`（HTTPS 时）+ `SameSite=Strict`；本地 HTTP 调试可用配置项关 Secure，但**代码默认值必须是安全的**
- 会话有过期时间；登出使会话失效

### 2.2 防爆破与限流

- 登录：同一 IP 连续失败 5 次锁定 15 分钟（429）
- 审计日志统一格式、带真实客户端 IP（反代后取 `X-Forwarded-For`），如 `AUTH login fail ip=...`，可直接对接 fail2ban 二次封禁
- 写操作/批处理接口：并发保护 + 冷却期（防重复触发、防资源耗尽）
- 通用 API 限流（网关层或应用层）

### 2.3 传输与响应头

- 全站 HTTPS（Caddy/证书自动化，避免人工续期遗忘）；启用 HSTS
- 安全响应头（反代层统一下发）：
  - `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`
  - **CSP 必须按应用实际形态配置并在真实浏览器验证**（真实踩坑：CSP 拦内联脚本、拦 Vue 的 eval，白屏两次才配对）
- HTTP 只是过渡态：无域名阶段可以 `:80` + `SECURE_COOKIE=false`，但必须记录为待办，域名就绪立即切回

### 2.4 注入与输入

- SQL：只走参数化查询/ORM/Mapper，**禁止字符串拼接 SQL**；业务代码不直接拼 SQL
- 所有外部输入（参数、Header、上传文件）校验长度/类型/白名单
- 输出按上下文转义（HTML/JS/URL）；富文本用白名单过滤
- 文件上传：限制类型/大小/存储路径，文件名服务端重生成

### 2.5 信息收口

- 生产环境错误响应不含堆栈/SQL/内网信息
- Swagger/api-docs/actuator 等端点：认证启用后必须收口到登录后，生产可整体关闭（踩坑：`/api-docs` 连字符前缀绕过 `startsWith("/api/")` 过滤——路径判断要显式列出所有管理端点前缀）
- 关闭目录列表、默认欢迎页、示例应用

### 2.6 依赖与供应链

- 依赖版本锁定（lock 文件/pom 定版），定期更新安全补丁
- 接入漏洞扫描：GitHub Dependabot / `mvn versions` / Trivy（镜像）
- 不引入"看起来常用"的库而不核实——先查项目已有依赖能否满足

### 2.7 密钥全生命周期

- 存储：环境变量或密钥管理服务；**严禁入仓**（含 git 历史——入过一次即视为泄露，删文件不够，要轮换）
- 预防：`.gitignore` 模板 + `gitleaks` 类扫描进 CI
- 轮换：任何泄露迹象（服务器被登、凭据出现在日志/截图）→ 不评估损失，直接全部轮换
- 分发：凭据只在部署目标机的受保护文件（600）中，文档里只写"从哪取"，不写值

### 2.8 日志

- 安全事件必记：登录成功/失败（含 IP）、管理操作、限流触发
- 日志不含口令、token、完整 Cookie；敏感字段脱敏
- 应用日志可 journalctl/文件采集，保留期 ≥ 30 天

## 三、流程层

### 3.1 上线前安全检查单（打勾制，缺一不可）

**装机层**
- [ ] `sshd -T` 确认密码认证已关；密码试登被拒；密钥登录正常
- [ ] fail2ban jail 运行中；安全组只放必需端口
- [ ] DB/管理端口确认仅 127.0.0.1（`ss -tlnp` 逐项核）

**应用层**
- [ ] 认证已启用；登录限流实测（连续错误 → 429）
- [ ] HTTPS 可访问；Cookie 属性正确（Secure/SameSite/HttpOnly）
- [ ] 安全响应头生效（`curl -sI` 核）；管理端点未登录 401
- [ ] 凭据文件权限 600；仓库内 `gitleaks` 扫描无密钥

**运维层**
- [ ] 备份脚本手动执行成功 + **恢复演练过一次**
- [ ] 干净基线快照已打；云控制台 MFA + 告警已开

### 3.2 入侵响应预案（提前写好，出事照做）

1. **断**：关闭密码认证（如还开着）、必要时安全组临时只放运维 IP
2. **换**：全部凭据轮换（DB/口令/第三方 token）——不评估"有没有被看到"
3. **查**：auth.log / 应用审计日志 / 新增用户 / crontab / 异常进程，确认入侵路径与范围
4. **重建**：无法 100% 确认干净 → 重装系统，按本规范第 1.1 节顺序重建（先焊门再装服务）
5. **录**：复盘写入踩坑文档（现象/根因/修法），转为规范条目

### 3.3 日常纪律

- 安全机制不可因"调试方便"在代码中默认关闭（配置项可以留，默认值必须安全）
- 文档即契约：安全相关行为变更必须同步更新本规范/架构文档
- 每季度过一遍：补丁、依赖漏洞、凭据轮换、快照有效性

## 附：本规范的血泪出处（stock-signal 项目实测）

- root 弱密码 + 密码认证未关 → 1630 次爆破被打穿（2026-07-27）→ 催生第〇章原则 3 与第 1.1 节装机顺序
- 重装部署当天 fail2ban 自动封禁 1 个爆破 IP（13 次失败）→ 扫描是持续常态
- CSP 拦内联脚本/拦 eval 白屏两次 → 第 2.3 节"安全头必须真机验证"
- `/api-docs` 前缀绕过认证过滤器 → 第 2.5 节显式列举端点
- mysqldump 权限报错 → 最小权限与备份参数（`--no-tablespaces`）的平衡
